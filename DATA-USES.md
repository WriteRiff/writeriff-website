# Data uses: WriteRiff website (writeriff.com)

Every kind of data the website collects or sends. Update the row in the same change that adds, changes or removes a data flow (shared rule, 2026-11-18). Feeds the privacy policy (the official text lives in the app repo, `C:\Users\scott\WriteRiff\docs\legal\`, published to `privacy/`).

Status 2026-11-21 (website audit, `C:\Users\scott\WriteRiff-Website\docs\audit-2026-11-21.md`): the site is live at writeriff.com (GitHub Pages, repo WriteRiff/writeriff-website). The form tables are live on the dev Supabase project (app repo migrations `supabase/migrations/202611200501_website_forms_dev.sql`, `202611200502_website_forms_review_fixes_dev.sql`, `202611201500_website_forms_round2_dev.sql`). Form email alerts to hello@writeriff.com are switched on.

| Data | Where it's collected | Where it's stored | Outside service that receives it | Why | How long it's kept | Linked to the person? |
|---|---|---|---|---|---|---|
| Beta sign-up: email (required), name and "what do you write" (optional), page signed up on, date/time | Beta form (home page and `beta/`) | Supabase table `beta_signups` (dev project `rnehrjdaruejuueztngc`) | Supabase (database host); Zoho ZeptoMail (alert email, row below). Later, the email service used to send beta emails | To email the person about the WriteRiff beta | Privacy policy: until the person unsubscribes or asks us to delete it. An unsubscribe turns news off but keeps the row (name, email, "what do you write"). Nothing deletes rows automatically yet (open question for the owners, audit 2026-11-21) | Yes (email address) |
| News opt-in (`marketing_opt_in`): the beta form has one unticked box that must be ticked to join, covering beta emails plus news, special offers and new features. Website sign-ups are sent with `true`; the database saves `false` instead when the address has an earlier unsubscribe, and a repeat sign-up leaves the existing row unchanged. The contact form has no opt-in. | Beta form | Same row as the sign-up | Supabase. Later, the email service used for news | To send WriteRiff news, special offers and new-feature emails to people who ticked the box | Until the person unsubscribes | Yes (email address) |
| Unsubscribe request: email address, date/time, how many times asked | `unsubscribe/` page (linked in every footer) | Supabase table `email_unsubscribes` | Supabase; Zoho ZeptoMail (alert email). The email service also handles the unsubscribe link in each email | To stop all WriteRiff news emails to that address, immediately (also turns news off on the beta list, contact rows and any app account with that email) | Kept so we never email that address news again | Yes (email address) |
| Contact message: name, email, topic, message, date/time | Contact form (`contact/`) | Supabase table `contact_messages` | Supabase; Zoho ZeptoMail (alert email) | To read and answer questions and suggestions | Privacy policy: as long as needed to answer, at most 2 years. Nothing deletes rows automatically yet (owner step) | Yes (email address) |
| Form alert emails: a copy of each new beta sign-up, contact message (including the message text) or unsubscribe request, sent to hello@writeriff.com | Sent by the Supabase Edge Function `writeriff-website-alert` after a form row is saved (only the table name and row id go to the function; it reads the row itself) | The hello@writeriff.com mailbox; ZeptoMail's sending logs | Zoho ZeptoMail (email delivery); the hello@ mailbox provider | So the owners see new sign-ups and messages without opening the database | Until deleted from the mailbox; ZeptoMail keeps sending logs about 60 days. Capped at 20 alerts an hour / 100 a day | Yes |
| Spam limit record: a SHA-256 hash of the visitor's network (IP) address, which form, date/time | Every form submission (the database reads the address PostgREST passes on) | Supabase, private table `writeriff_private_dev.website_rate_dev` | Supabase | Per-sender limits so one script can't flood the forms (beta and unsubscribe 10 an hour / 30 a day, contact 5 an hour / 20 a day) | Rows older than 1 day are removed the next time someone submits a form | Hashed IP only (not linked to the form row) |
| Intro "already seen" flag (`wr-intro-seen`) | Every public page with the opening animation (not `account-callback/`) | The visitor's own browser (localStorage); never sent anywhere | None | So the opening animation plays only once per visitor | Until the visitor clears their browser data | No |
| Cloudflare Web Analytics: page views and visits (page address, referrer, browser and device type, country, page load timing) | Every website page except `account-callback/` (small script from static.cloudflareinsights.com) | Cloudflare (aggregated counts in the Beckman Studios Cloudflare account) | Cloudflare | To count visits and see which pages people read | Cloudflare's own retention for Web Analytics | No: no cookies or browser storage, no fingerprinting, no cross-site tracking; Cloudflare's servers see the IP address to deliver the script |
| Monthly report: visit totals, top page addresses, referring site names, broken links, renewal dates | GitHub Action `monthly-report.yml` (reads Cloudflare's totals) | Not stored; sent once a month | Pushover (to the owners' phones) | So the owners see how the site is doing without running anything | Pushover's own retention | No (totals only; a page address could in theory contain something a visitor typed) |
| Downtime alarm: the site address and whether it loaded | GitHub Action `uptime.yml`, every 5 minutes | Up/down state on the repo's `uptime-state` branch | Pushover (to the owners' phones) | To alert the owners when the site is down | State file kept on the branch (last 50 incidents) | No personal data |
| Standard web server logs (IP address, browser, page requested) | Every request | Hosting provider (GitHub Pages) | GitHub | Security and keeping the site working (we don't use these) | GitHub's own retention | Not by us |
| Account pages (`account-callback/`, `delete-account/`) | Links in WriteRiff app emails (callback); the deletion guide is a plain page | Nothing stored by the website; the callback page talks directly to Supabase Auth to confirm an email or set a new password. `delete-account/` only explains how to delete an account (in the app or by email) | Supabase Auth (callback only) | Part of the app's account system (covered by the app's own DATA-USES.md) | n/a | (app account) |

Not used: cookies, advertising or tracking scripts, third-party fonts or embeds. The only outside script is Cloudflare Web Analytics (cookieless, row above), described in the privacy policy's website section.
